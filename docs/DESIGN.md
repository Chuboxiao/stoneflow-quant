# 设计与扩展约定

[实验室总览](../README.md) · [回测系统](../README_BACKTEST.md) · [策略研究](../README_RESEARCH.md) · [因子评价](../README_FACTORS.md)

穿石遵循一条研究逻辑：**按当时可知的数据形成信号，用明确规则尝试交易，保存可核对的结果，再解释证据。**

## 模块各管什么

| 层次 | 职责与接口 | 当前实现 |
| --- | --- | --- |
| 数据 | 对齐交易日与证券，保留原价和cumadj，提供截至当前时点的历史 | `backtest/data.py`的`MarketData`；`backtest/precision.py`的`Panel`与历史状态加载 |
| 信号 | 计算当日分数；方向、窗口与公式写入定义 | `factorlab/core.py`的`FactorSpec`、`FactorContext`与注册表 |
| 策略 | 根据历史、信号与当前持仓，形成目标仓位；可保存内部状态 | `backtest/strategy.py`、突破策略及`factorlab/portfolio.py`的`FactorPortfolio` |
| 执行与记账 | 检查成交条件、数量、现金、费用及公司行为，记录成交和拒单 | 原版`BacktestEngine`／`SimBroker`；原始股份`PrecisionEngine` |
| 研究与结果 | 固定实验参数、保存指标和逐笔记录，检查来源与账本，解释结果 | 各`research*.py`、`strategy_analysis.py`、`factorlab/runner.py`与`results/` |
| 操作与展示 | 提交明确的研究任务、展示状态和结果、导出报告 | `web_server.py`、`web/dist/`、`factorlab/presentation.py`与`report_site/` |

当前两种账户模型分别保留：旧个股实验使用复权单位账户，全池精度研究使用原始股份、现金及公司行为账户。报告记录所用模型，不直接拼接两类收益。设计约定描述现有边界与后续扩展方式，并不表示已经统一了全部历史实现。

## 文档只承担一种主要职责

| 文档或目录 | 放什么 |
| --- | --- |
| `README.md` | 项目介绍、启动入口、模块导航和当前能力 |
| `README_BACKTEST.md` | 回测系统怎么使用和扩展，账户与成交边界 |
| `README_RESEARCH.md` | 策略实验设计、关键结果、收益口径与报告入口 |
| `README_FACTORS.md` | 因子评价怎么使用、5DR演示及扩展入口 |
| `docs/` | 启动、设计、公式、数据与执行精度、发布方法 |

主README保留导航与项目能力。新增模块使用有明确名称的说明文件，例如`README_FACTORS.md`；已有模块的新实验放进研究结果目录及对应报告，避免按课堂次序继续扩充主README。课程背景和要求对应集中放在策略研究说明中。

## 新增功能放在哪里

1. **新因子**：定义`FactorSpec`和时点builder，或导入已知时点的CSV；评价统计继续使用`factorlab`。需要交易时用`FactorPortfolio`接入执行层。
2. **新策略**：通过策略接口读取历史与模拟持仓，返回目标仓位。持仓和现金继续由账户模型维护。
3. **新交易约束**：在对应执行模型中实现，记录拒单原因与账户变动，补充有明确预期的小样本测试。
4. **新研究**：声明区间、股票池、方向、参数和账户模型，保存到独立的`results/<研究>/`目录；派生报告从同一份结果读取数字。
5. **新网页**：展示现有接口与结果，运行任务明确经过后端；数据不足、缺少净交易账户或任务失败时显示实际状态。

## 共同约定

- **时点**：当日信号只读取截至当日的数据；未来报价只用于评价标签，执行遵循已声明的下单时序。
- **口径**：因子报价收益与净交易收益、累计与年化、训练与评价区间分别标注；对照时保持可比较的条件。
- **复现**：保存参数、来源、运行状态与逐笔记录；修改定义或交易规则后保留历史版本与对应结果。
- **验证**：测试检查有经济含义的行为，例如未来数据不改变过去信号、涨停拒买、缺失不填零、账本可重放。
- **数据管理**：原始行情、辅助缓存、本机路径和临时运行与源码分开。当前忽略规则见[.gitignore](../.gitignore)。

## 后续能力的边界

现有系统覆盖日频历史研究与模拟交易。未来若接入个人投资账户，券商连接、实盘订单生命周期、资金与风险约束属于执行层的新能力；研究网页与因子评分继续作为研究工具。行业／市值中性化等统计扩展则进入因子评价层，并声明所需数据与方法。

源码、数据、研究结果及报告各自保留清楚的来源与用途，有助于后续维护、复核与公开协作。
