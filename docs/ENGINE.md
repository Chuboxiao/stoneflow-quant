# 第四讲任务一：日频回测系统

本项目把七个 Feather 日频矩阵接入一个可运行的事件驱动回测系统。你可以查看历史行情、接入策略、生成下一交易日订单、模拟成交、更新账户，并检查净值和每笔未成交原因。

本次选用 **603950.SH 长源东谷**和 **002230.SZ 科大讯飞**。这是用于学习系统结构的选择，不是投资建议。长源东谷的首个有效行情日期为 2020-05-26，共同演示区间为 **2020-05-26 至 2026-10-16，1,550 个交易日**。

## 先查看已经生成的报告

- [演示报告](results/demo/report.html)：使用真实 Feather 数据和明确标注的保守涨跌停代理。
- [严格模式检查](results/strict_audit/report.html)：未提供精确涨跌停资料，所有相关订单拒绝成交，账户保持现金。这是缺资料的安全行为，不是策略有效性结论。
- [独立核对结果](results/validation.json)：记录全量运行的账目一致性、信号时间和严格模式检查。

演示规则仅用于验证系统：每 20 个交易日给两只股票各分配 49% 目标仓位，留 2% 现金；收盘决策、下一交易日开盘执行。**任务二已实现普通突破与成交额确认突破；不采用老师的5日最低收益示例。**

## 安装和运行

需要 Python 3.10 或以上。原始 Feather 数据留在原文件夹，不复制、不修改。

在此项目目录打开终端，第一次运行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_demo.py
```

示例的数据路径和两只股票写在 `examples/demo_config.json`。可编辑该文件，也可以覆盖命令行参数：

```bash
python run_demo.py --start 2021-01-01 --end 2025-12-31 --cash 1000000 --output results/my_run
```

`run_demo.py` 明确选择 `conservative` 模式。直接运行 CLI 的默认模式则为 `strict`：

```bash
python -m backtest.cli \
  --data-dir 'data/feathers' \
  --symbols 603950.SH 002230.SZ \
  --limit-mode strict \
  --limits-csv /path/to/daily_limits.csv \
  --output results/strict_with_limits
```

不提供 `--limits-csv` 也能运行 strict，但相关订单会因资料不足而拒绝；不能把此时的零收益解释成策略表现。

更多参数用 `python -m backtest.cli --help` 查看。可以设置初始资金、调仓间隔、目标总仓位、佣金、最低佣金、滑点和每手数量。总权重不超过 1，不允许做空或杠杆。

## 代码各部分负责什么

| 文件 | 职责 |
|---|---|
| `backtest/data.py` | 按证券列读取七个矩阵，检查日期对齐，提供原价和复权历史 |
| `backtest/clock.py` | `SimClock` 依次产生开盘、收盘事件 |
| `backtest/strategy.py` | 限定日期的 `StrategyContext` 和示例策略接口 |
| `backtest/broker.py` | `SimBroker` 接收目标仓位，先卖后买，执行约束、成本与记账 |
| `backtest/limits.py` | 精确涨跌停资料接口、保守代理、停牌标记 |
| `backtest/engine.py` | 串起时钟、策略、券商、账户快照和统计 |
| `backtest/report.py` | 导出 CSV、JSON 和无需联网的 HTML 报告 |
| `backtest/models.py` | 配置、费用模型、订单结构 |
| `tests/test_backtest.py` | 41 项针对交易与记账的测试 |
| `examples/custom_strategy.py` | 如何替换为自己的策略 |

策略通过接口使用历史行情和目标仓位，无需直接操作 Feather 文件或手工修改账户。`SimClock` 和 `SimBroker` 是模拟环境实现；目前没有连接真实券商、没有实盘下单能力。

执行顺序固定为：

```text
交易日 T 开盘：执行 T-1 收盘后生成的目标仓位
  → 检查开盘价、因子、涨跌停、停牌、资金、可卖持仓
  → 先尝试卖出，再用实际可用现金尝试买入
交易日 T 收盘：估值、保存账户和持仓
  → 策略只读取截至 T 日的历史副本
  → 策略返回目标仓位，等待下一交易日开盘
```

最后一天的信号标记为 `OUTSIDE_BACKTEST_RANGE`，不会虚构一次下一日成交。期末不强制清仓，结果是持仓收盘估值。

## 必须理解的两个数据边界

### 一、使用 cumadj，但没有虚构真实分红账本

这套资料只有累计复权因子，无法单独确定每次现金分红、送股、配股的详细数量及到账日期。因此系统采用**复权单位教学账户**。

每只证券取已加载历史中首个有效累计因子为固定基准 `A_ref`：

```text
scale_t = cumadj_t / A_ref
复权单位价格 = 原始价格 × scale_t
持仓市值 = 复权单位数量 × 复权单位价格
成交等价股数 = 复权单位数量 × scale_t
```

买入时先按当日原价和等价股数确定成交额，再换算为复权单位。持有期间单位数不变，复权价格体现因子的变化。撮合和涨跌停比较始终使用**原始价格**，不把复权价格当作实际盘口价格；不对成交额和成交笔数做复权。

例如：原价 10 元、因子 1 时买入 100 股，随后发生 1 拆 2，原价 5 元、因子 2。持有的 100 个复权单位仍值 1,000 元，等价股数变成 200。不能把现金分红导致的所有因子变化也解释成实际送了股票，所以输出明确称为 `raw_equivalent_qty`，而不是实际登记股数。

这个模型适合检查复权收益、系统流程；它不等于精确的券商现金与公司行为账本，也不能保证还原特定红利再投资约定。需要真实现金分红、税、登记股数、配股出资时，须补充逐笔公司行为资料再扩展账本，不能从一个累计因子臆造。

### 二、严格模式与保守代理有明确区别

老师要求涨停不能假定买到。本系统在**提供精确资料时**，计划成交时点的原始开盘价达到涨停价就拒绝买入；达到跌停价就拒绝卖出。即使当天高低价或成交额显示后来有成交，也不会据此假定自己在开盘排队成交。

`strict`：必须有当日、当只证券的外部涨跌停/停牌记录。没有就返回 `MISSING_PRICE_LIMITS`，不默认成交。外部文件内容由提供者保证真实、当时已知；系统验证结构和重复值。

`conservative`：缺少外部资料时，用以下**代理保护**：

```text
估计除权参考前收 = 上一交易日原始收盘价 × 上一日因子 / 当日因子
买入保护价 = 向下取整到分(参考前收 × 1.05) − 0.01
卖出保护价 = 向上取整到分(参考前收 × 0.95) + 0.01
```

达到买入保护价则不买，达到卖出保护价则不卖。代理不把不同板块全部当作 10%：它采用更严格的常见 5% 边界保护，可能拒绝原本可以成交的订单。**因子还原参考价仍是估计，这不能证明准确识别所有历史涨跌停。**报告明显标注代理模式，演示结果不能称为精确成交回测。

外部精确记录优先于代理。若上一日价格或因子无效，代理也拒绝成交。没有使用当日收盘、高低价判断开盘成交。全天成交额非正或缺失仅用于事后否决不可能的成交，未作为盘前选股信息或成交容量估计。

## 精确涨跌停资料格式

空模板为 `examples/daily_limits_TEMPLATE.csv`，列名如下：

```text
date,symbol,upper_limit,lower_limit,no_limit,suspended
```

- `date`：交易日，格式 YYYY-MM-DD。
- `symbol`：例如 603950.SH，与 Feather 列名一致。
- `upper_limit`、`lower_limit`：官方或可靠数据源提供的**原始价格**涨跌停价。
- `no_limit`：无涨跌幅限制日写 1，否则 0；不能把缺失资料写成 1。
- `suspended`：当日停牌写 1，否则 0。
- 普通交易日两项价格必须有效；无涨跌幅限制或停牌的记录可留空价格。
- `(date, symbol)` 必须唯一。严格模式下，请覆盖整个回测区间的所选证券。

系统不自动假设股票始终非 ST，也不根据当前股票名称倒推历史 ST 状态。输入精确价可覆盖历史板块规则变化、特殊上市日期等情况。

## 费用、成交及缺失数据

- 默认佣金万三、每笔最低 5 元；双向滑点 5 bps，并向不利方向取整到分。
- 股票卖方印花税：2023-08-28 之前千分之一，此后万分之五。不包含全部真实收费项目，如过户费。
- 买入先预留费用，保证现金非负；不足整手时拒单，资金不足时可按整手缩小订单。
- 示例每手 100 个原价等价股，适用于本次主板教学对象。尚未完整实现科创板最低申报量等全部板块规则。
- T+1：本日买入的复权单位本日不可卖，旧持仓仍可卖。
- 日频开盘撮合没有盘口排队、容量限制和盘中路径；不根据收盘才知道的当日成交额倒推开盘流动性。
- 开盘价或因子缺失，订单不成交。持仓收盘价缺失，用最近一次有效价格估值并明确标记 `stale_valuation`，不拿 0 估值或假清仓。
- 退市后持续缺失行情的仓位会保留旧估值并标记；涉及这些记录的收益须单独复核，不能当作已退出仓位。
- 年化收益、波动、夏普使用每年 252 个交易日，夏普无风险收益率设为 0。没有输出无法由当前模型可信确定的胜率。

## 输出字段

| 文件 | 主要内容 |
|---|---|
| `equity.csv` | 每日现金、市值、总资产、净值、收益、回撤、费用、旧估值数量 |
| `orders.csv` | 信号/执行日期、方向、申请与成交等价股数、复权单位、原始/复权成交价、费用、拒单原因 |
| `positions.csv` | 每日每只证券的复权单位、等价股数、市值、权重、估值时点 |
| `signals.csv` | 收盘信号和目标权重；期末未执行信号单独标记 |
| `metrics.json` | 收益和风险统计、成交/拒单数量及原因 |
| `metadata.json` | 原始数据位置、缺失数量、因子基准、配置、策略参数和模型假设 |
| `report.html` | 可直接打开、无需联网的图表和运行记录 |

`PARTIAL` 包含按整手或现金缩减数量，表示意图没有完全实现；不是使用盘口模拟了真实部分成交。HTML 只显示最近 30 条成交和拒单，CSV 保存全部记录。
